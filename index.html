The 8-Puzzle Problem

The 8-Puzzle is a classical problem in Artificial Intelligence used to demonstrate and evaluate search algorithms. It consists of a 3×3 grid containing eight numbered tiles (1–8) and one blank tile (represented as 0).

The objective is to reach a goal configuration from an arbitrary initial configuration by sliding tiles into the blank space. This is modeled as a state-space search problem.

Initial State: Goal State:
1 2 3 1 2 3
4 _ 5 4 5 6
7 8 6 7 8 _

State Space: 9!/2 = 181,440 reachable states

Solvability Algorithm

A puzzle is solvable if and only if the number of inversions in the initial state has the same parity as the number of inversions in the goal state.

An inversion occurs when a higher-numbered tile appears before a lower-numbered tile in row-major order (blank excluded).

Key Observations

Why GBFS varies by puzzle

  • Performance depends heavily on the heuristic quality
  • Manhattan Distance typically outperforms Misplaced Tiles
  • GBFS may explore more nodes on "deceptive" puzzles
  • Tie-breaking rules affect the exact expansion order

GBFS vs A* Trade-offs

  • GBFS is typically faster than A* (ignores g(n))
  • A* guarantees optimal solutions; GBFS does not
  • GBFS uses less memory in practice for good heuristics
  • A* is complete; GBFS is not in infinite spaces

1. What is GBFS?
Greedy Best-First Search is a heuristic search algorithm that selects the next node to expand based solely on the heuristic function h(n). Unlike A*, it does not consider the cost already incurred to reach the current node (g(n)). The evaluation function is simply f(n) = h(n).
2. How GBFS Selects the Next Node
GBFS maintains a priority queue (the frontier/open list) ordered by h(n). At each step, it dequeues the node with the lowest h(n) value — the node that appears "closest" to the goal according to the heuristic. This greedy strategy gives it its name.
3. The Priority Queue (Frontier)
The frontier is implemented as a binary min-heap ordered by h(n). Insertion is O(log n). Extraction of the minimum is O(log n). Tie-breaking is deterministic (FIFO by insertion order). Nodes already in the explored set are never re-added.
4. The Explored Set (Closed List)
To prevent re-expansion of states, GBFS maintains a hash set of explored state keys (string representations of the tile array). Before expanding successors, each successor's key is checked against the explored set. If found, the successor is discarded.
5. Why GBFS is NOT Optimal
Because GBFS ignores g(n), it may take a longer path to the goal. The heuristic guides it toward the goal quickly, but the path taken may not be the shortest. A puzzle with a deceptive heuristic landscape can cause GBFS to find a suboptimal solution or get stuck in a local minimum.
6. Why GBFS is NOT Complete in Infinite Spaces
In an infinite search space, GBFS can get trapped in an infinite loop following states that appear closer to the goal but lead away from it. With a finite state space and a closed list (explored set), GBFS becomes complete — it will not re-expand states.
7. Heuristic Quality Influence
The quality of the heuristic strongly influences GBFS performance. A perfect heuristic (h(n) = h*(n)) makes GBFS run in linear time. A weak heuristic (e.g., h(n) = 0) degrades GBFS to BFS. Manhattan Distance dominates Misplaced Tiles and generally causes fewer node expansions.

GBFS vs A* — Key Distinction
⚡ Greedy Best-First Search
f(n) = h(n)
  • Only uses heuristic estimate h(n)
  • Ignores path cost g(n)
  • Fast but not optimal
  • Not complete in infinite spaces
  • Memory: stores full frontier
🌟 A* Search
f(n) = g(n) + h(n)
  • Balances path cost g(n) and heuristic h(n)
  • Optimal with admissible heuristic
  • Complete with admissible heuristic
  • Expands fewer nodes than BFS
  • More memory-intensive than GBFS

Heuristic Functions — Mathematical Detail

h₁: Misplaced Tiles

h₁(n) = Σ [tile_i ≠ goal_i AND tile_i ≠ 0]
for i = 0..8

Count the number of non-blank tiles not in their goal position. Each such tile requires at least one move to reach its goal, making this heuristic admissible (never overestimates).

Example
Current: [1,2,3,4,0,5,7,8,6]
Goal: [1,2,3,4,5,6,7,8,0]
Misplaced: tiles 5,6,8,0→ h₁ = 3

h₂: Manhattan Distance

h₂(n) = Σ (|currRow(t)-goalRow(t)|
+ |currCol(t)-goalCol(t)|)
for each tile t ≠ 0

For each tile, sum the minimum number of moves needed to reach its goal position moving only horizontally and vertically. Dominates Misplaced Tiles (h₂(n) ≥ h₁(n) always).

Example
Current: [1,2,3,4,0,5,7,8,6]
Goal: [1,2,3,4,5,6,7,8,0]
Tile 5: pos(1,2)→goal(1,1) = 1
Tile 6: pos(2,2)→goal(1,2) = 1
Tile 8: pos(2,1)→goal(2,1) = 0
h₂ = 1+1+0+... = 2

GBFS Pseudocode
function GBFS(initial, goal, heuristic): frontier = PriorityQueue() frontier.push(h(initial, goal), initial) explored = Set() while frontier is not empty: node = frontier.pop() // Remove node with lowest h(n) if node is goal: return reconstruct_path(node) if node in explored: continue explored.add(node) for each successor in expand(node): if successor not in explored and successor not in frontier: hVal = h(successor, goal) // f(n) = h(n) ONLY (no g(n)) frontier.push(hVal, successor) return FAILURE // No solution found
⚠ Key Distinction from A*

In the code above, frontier.push(hVal, successor) uses only h(n) as the priority. A* would use frontier.push(g(successor) + h(successor, goal), successor) — adding the path cost g(n). This single difference makes A* optimal and GBFS not optimal.

Other Search Algorithms — Theoretical Reference

BFS — Breadth-First Search

f(n) = depth(n) | FIFO queue

Complete and optimal (unit costs). Explores level by level. High memory usage O(b^d).

DFS — Depth-First Search

f(n) = depth(n) | LIFO stack

Not complete (loops), not optimal. Low memory O(bm) but can miss solutions.

DLS — Depth-Limited Search

DFS with cutoff depth l

Incomplete if solution depth > l. Useful when upper bound on depth is known.

IDDFS — Iterative Deepening

Repeat DLS with l = 0,1,2,...

Complete and optimal (unit costs). Combines DFS memory efficiency with BFS completeness.

Project Description

This project implements the Greedy Best-First Search (GBFS) algorithm to solve the classic 8-Puzzle problem with a complete interactive visualization interface.

The application provides step-by-step visualization of the search process, including frontier management, explored state tracking, heuristic value display, and solution path reconstruction.

Two admissible heuristics are implemented: Misplaced Tiles (h₁) and Manhattan Distance (h₂), allowing users to compare their effect on search performance.
